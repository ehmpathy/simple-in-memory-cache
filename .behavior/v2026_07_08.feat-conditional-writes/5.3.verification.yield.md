**grain note (two distinct triggers — do not conflate them):** per `rule.require.test-coverage-by-grain`,
transformers → unit, communicators/orchestrators → integration, contracts → **acceptance**. these are
**two separate triggers**:

- **integration** exists to catch **i/o-boundary** regressions. this feature has **none**: `createCache`
  is a pure factory, and `isLive` / `assertConditionMet` / `getLiveEntry` / `nextVersion` / `version` /
  `get` / `set` are pure in-memory transformers with no network / db / filesystem (the store is a
  closure-scoped object). so **no integration tests** — correct, there is no i/o boundary to test.
- **acceptance** exists because **contracts face humans/consumers** — its trigger is "a public contract
  ships", **not** "the code touches i/o". this feature ships a new public sdk contract
  (`WithCacheConditionals` conformance + the widened `get`/`set` + `version`), so it **does** warrant
  acceptance coverage. `src/index.acceptance.test.ts` provides it: it drives all three vision usage
  patterns (put-if-absent claim, mutex acquire→renew→release, optimistic round-trip) end-to-end through
  the **published `./index` barrel entry** — the single module that compiles to `dist/index.js`, the
  surface a consumer imports via `simple-in-memory-cache`. it proves every symbol a consumer needs is
  exported from the barrel and that all three journeys compose through it, and it snapshots both the
  positive outcome (success value) and negative outcome (error message) of each journey. it imports the
  barrel by relative path (resolves to `src/index.ts`, the source of `dist/index.js`), so it validates
  the export surface — not the `package.json#main` resolution, which the `build` step in
  `test:acceptance` validates separately when it compiles `dist`.

net: unit covers the pure transformers, acceptance covers the published contract journeys; integration is
correctly empty (no i/o boundary).
