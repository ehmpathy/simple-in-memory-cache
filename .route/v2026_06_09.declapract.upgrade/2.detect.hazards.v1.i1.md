# 2.detect.hazards — hazard detection report

## summary

reviewed `git diff --cached` for changes from declapract upgrade. identified hazards in test, cicd, and config categories.

---

## test hazards

### 1. jest globals import required

**what changed**: jest.integration.env.ts now imports `import { jest } from '@jest/globals'`

**why it may break**: if any test files reference `jest` global without this import, typescript will error.

**how to verify**: `rhx git.repo.test --what types`

### 2. slowtest reporter added

**what changed**: jest configs now include `test-fns/slowtest.reporter.jest` reporter.

**why it may break**: if `test-fns` package is not properly installed, tests will fail to start.

**how to verify**: `rhx git.repo.test --what unit --mode apply`

### 3. apikeys system replaced with keyrack

**what changed**:
- `.agent/repo=.this/role=any/skills/use.apikeys.json` deleted
- `.agent/repo=.this/role=any/skills/use.apikeys.sh` deleted
- jest.integration.env.ts now uses `keyrack.source()` instead

**why it may break**: if tests relied on the old apikeys system, they may fail due to absent credentials.

**how to verify**: `rhx git.repo.test --what integration --mode apply`

## cicd hazards

### 1. keyrack firewall step added

**what changed**: `.github/workflows/.test.yml` now includes `keyrack firewall` step.

**why it may break**: requires `SECRETS_JSON` from GitHub secrets. if secrets not configured, tests may fail.

**how to verify**: push to branch, watch CI

### 2. jest api changed

**what changed**: `--testPathPattern` → `--testPathPatterns`

**why it may break**: jest 30.x uses new flag name. already fixed in workflow.

**how to verify**: push to branch, watch CI

### 3. aws oidc auth added

**what changed**: `test.yml` now passes `creds-aws-role-arn: ${{ vars.CREDS_CICD_AWS_DEV_OIDC_ROLE_ARN }}`

**why it may break**: if this GitHub variable is not set, AWS tests may fail (if any exist).

**how to verify**: check if repo uses AWS. if not, no impact.

## config hazards

### 1. env var renamed: STAGE → CONFIG

**what changed**: jest.integration.env.ts checks `process.env.CONFIG` instead of `process.env.STAGE`

**why it may break**: if processes set `STAGE`, they need to set `CONFIG` instead.

**how to verify**: search codebase for `STAGE=` references

### 2. env var renamed: I_KNOW_WHAT_IM_DOING → I_KNOW_THE_RISKS

**what changed**: safety check renamed in jest.integration.env.ts

**why it may break**: if other tools use old env var name, tests will throw.

**how to verify**: search codebase for `I_KNOW_WHAT_IM_DOING` references

### 3. dpdm cycle detection added

**what changed**: new `test:lint:cycles` command in package.json uses dpdm.

**why it may break**: if codebase has circular imports, lint will fail.

**how to verify**: `rhx git.repo.test --what lint`
