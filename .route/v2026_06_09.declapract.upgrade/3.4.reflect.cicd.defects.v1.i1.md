## defect 1: keyrack firewall failure

### classification: repo quirk

### rationale

#### what the practice template provides

the declapract-typescript-ehmpathy practice template:

1. **keyrack.yml.declapract.ts** uses `FileCheckType.EXISTS` — it only checks that `.agent/keyrack.yml` exists, without content constraints

2. **package.json** (src/practices/rhachet/best-practice/) has:
   ```
   "prepare:rhachet": "rhachet init --keys --hooks --roles mechanic behaver driver reviewer librarian ergonomist architect"
   ```

3. **the declapract repo's own keyrack.yml** only extends:
   ```yaml
   extends:
     - .agent/repo=ehmpathy/role=mechanic/keyrack.yml
   ```

#### what this repo has

this repo's keyrack.yml extends three roles:
```yaml
extends:
  - .agent/repo=bhrain/role=reviewer/keyrack.yml
  - .agent/repo=bhuild/role=dispatcher/keyrack.yml
  - .agent/repo=ehmpathy/role=mechanic/keyrack.yml
```

the `reviewer` and `dispatcher` extends are NOT from the practice template.

#### search evidence

```sh
$ gh search code --repo ehmpathy/declapract-typescript-ehmpathy "dispatcher"
# (no results)

$ gh search code --repo ehmpathy/declapract-typescript-ehmpathy "repo=bhuild/role=dispatcher"
# (no results)
```

the practice template has no reference to dispatcher.

#### conclusion

the keyrack.yml extends were customized for this repo beyond the practice template baseline. when the practice template's prepare:rhachet roles list was applied, it naturally didn't include dispatcher (since dispatcher is not part of the practice template).

this is a **repo quirk**, not a practice bug. the fix (add dispatcher to prepare:rhachet) is correct for this repo's customized keyrack.yml configuration.

### action required

none. the fix is local to this repo. no practice template update needed.
